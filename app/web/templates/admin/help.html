Fluxo

  1. Entrada. Syslog (TLS 6514, TCP ou UDP 514), coleta por API (WithSecure, Cortex XDR, Vision One, WatchGuard EPDR, Axur, Tenable) ou upload de arquivo.
  2. Firewall. Só os IPs liberados em “Firewall do syslog” conseguem conectar. O servidor aplica as mudanças em até 1 minuto.
  3. Parsing determinístico. Cada linha passa pelo parser da fonte (ou autodetecção) e vira um evento normalizado (OCSF). Mesma linha, mesmo resultado — sem IA em produção.
  4. Saída. O evento é convertido no formato do destino (UDM para Google SecOps, JSON para Wazuh, LEEF para QRadar, CEF, OCSF, CSV) e enviado em lote, com reenvio automático. Também dá para baixar como .txt.
  5. Não reconhecidos. Linhas que nenhum parser entende ficam em “Não reconhecidos”. De lá, um clique pede ao Estúdio IA um parser novo ou ajuste — a IA gera, o motor testa, um administrador publica.
  6. Buffer curto. Eventos ficam 2 h; o que não foi entregue (destino fora do ar) fica até 24 h.

Configurar os equipamentos

{{ syslog_box(syslog) }}
rsyslog (TLS)
global(DefaultNetstreamDriverCAFile="/etc/ssl/certs/ca-certificates.crt")
action(type="omfwd" target="{{ syslog.host }}" port="{{ syslog.tls }}" protocol="tcp"
       StreamDriver="gtls" StreamDriverMode="1" StreamDriverAuthMode="x509/name"
       StreamDriverPermittedPeers="{{ syslog.host }}" TCP_Framing="octet-counted")
WatchGuard Firebox: Sistema → Logging → Syslog → servidor {{ syslog.ip }}, porta {{ syslog.tcp }}, TCP ou UDP (o Firebox não envia com TLS).

EVA — suporte por IA

Escreva para eva-trustparser@trustcontrol.nuvem.tec.br (ou pela API) pedindo dúvidas, ajustes de tela, cadastro de fontes/destinos/IPs ou um parser novo. Só quem está na lista de autorizados (Sistema → EVA) é atendido.
